# Git ワークフロー

## コミットメッセージ形式

```
<タイプ>: <説明>

<任意の本文>
```

**タイプ一覧**:
- `feat`: 新機能
- `fix`: バグ修正
- `refactor`: リファクタリング
- `docs`: ドキュメント
- `test`: テスト
- `chore`: 雑務（依存更新、設定変更等）
- `perf`: パフォーマンス改善
- `style`: UI/スタイル変更

## ブランチ戦略

```
main (本番)
  └── develop (開発メイン)
        ├── feature/xxx (機能開発)
        ├── fix/xxx (バグ修正)
        └── refactor/xxx (リファクタリング)
```

## プルリクエストワークフロー

PR作成時は以下の手順を遵守：

1. **全コミット履歴を分析**（最新コミットだけでなく）
2. `git diff develop...HEAD` で全変更を確認
3. 包括的なPRサマリーを作成
4. テスト計画を含める
5. 新規ブランチの場合は `-u` フラグ付きでpush

## 機能実装ワークフロー

### 1. 計画
- `/plan` で要件を整理
- 影響範囲を事前に確認

### 2. 実装
- 小さな単位で変更
- 各変更後にアプリの動作確認

### 3. コードレビュー
- `/code-review` を使用
- CRITICAL と HIGH の問題は必ず対処

### 4. コミット & プッシュ
- Conventional Commits 形式に従う
- 意味のある単位でコミット

## 禁止事項

- `git push --force` を main/develop に実行しない
- `git reset --hard` で他者のコミットを消さない
- 認証情報をコミットしない（`.env`, `*.key`, `*.pem` 等）
- `node_modules/` をコミットしない
- Firebase の秘密鍵をコミットしない
