# Famly コードレビューチェックリスト

本書はFamlyプロジェクト向けにカスタマイズしたレビューチェックリストです。
バージョンごとに意識すべきレベルを分けています。

---

## バージョン別 適用レベル

| レベル | 対象バージョン | 説明 |
|--------|---------------|------|
| 🔴 必須 | v0.1〜 (MVP) | 最低限守るべき項目。これを満たさないとリリース不可 |
| 🟡 推奨 | v1.0〜 (マネタイズ) | 品質向上のため積極的に適用。ユーザー増加に備える |
| 🟢 理想 | v2.0〜 (技術刷新) | スケール・長期運用を見据えた項目 |

---

## 1. 全般

### 🔴 必須 (v0.1〜)
- [ ] コードは他の人が理解できるように書かれているか
- [ ] 似ているコードは似たように書けているか（一貫性）
- [ ] 既存のコードパターンに従っているか

### 🟡 推奨 (v1.0〜)
- [ ] 仕様やコードを簡単な言葉で説明できるか
- [ ] 関連するまとまりでコードがグルーピングされているか

---

## 2. 凡ミス防止

### 🔴 必須 (v0.1〜)
- [ ] PR前に1行ずつ自分の変更したコードを確認したか（セルフレビュー）
- [ ] 英単語のスペルが正しいか
- [ ] 未使用の変数や関数を削除したか
- [ ] デバッグ用のconsole.logを削除したか
- [ ] 実機（Expo Go）で動作確認したか
- [ ] 主要なユースケースを一通り動作確認したか

### 🟡 推奨 (v1.0〜)
- [ ] すべての分岐パターンを動作確認したか
- [ ] エラーケースの動作確認をしたか

---

## 3. 要件・設計

### 🔴 必須 (v0.1〜)
- [ ] タスクの要件を満たしているか
- [ ] 曖昧な仕様がないか（不明点は確認したか）

### 🟡 推奨 (v1.0〜)
- [ ] ユースケースを洗い出せているか
- [ ] 境界値・例外ケースを考慮しているか
- [ ] 仕様をドキュメント（docs/）に残しているか

### 🟢 理想 (v2.0〜)
- [ ] シーケンス図やER図で全体の流れを可視化しているか
- [ ] API定義書を整備しているか

---

## 4. 命名

### 🔴 必須 (v0.1〜)
- [ ] 明確で具体的な名前を選んでいるか（曖昧な名前を避ける）
- [ ] 汎用的すぎる名前（temp, data, info）を避けているか
- [ ] TypeScript: キャメルケース（変数・関数）、パスカルケース（型・コンポーネント）
- [ ] Firestore: スネークケース（コレクション・フィールド）
- [ ] bool型はis/has/can/shouldで始まっているか

### 🟡 推奨 (v1.0〜)
- [ ] 単数/複数を意識しているか
- [ ] ドメイン用語（Task, Household等）と一致しているか

---

## 5. 変数

### 🔴 必須 (v0.1〜)
- [ ] 変数のスコープは必要最小限か
- [ ] 不要な一時変数を作っていないか
- [ ] なるべくconstを使っているか（再代入を避ける）

### 🟡 推奨 (v1.0〜)
- [ ] 変数の取りうる値を全パターン考慮しているか
- [ ] nullやundefinedの可能性を考慮しているか

---

## 6. 関数

### 🔴 必須 (v0.1〜)
- [ ] 関数名が処理内容を表しているか
- [ ] 引数は必要最小限か
- [ ] async/awaitのエラーハンドリングができているか（try-catch）
- [ ] 戻り値の型を明示しているか

### 🟡 推奨 (v1.0〜)
- [ ] 1つの関数が1つのことだけをしているか（単一責任）
- [ ] 関数が長すぎないか（目安: 50行以内）
- [ ] 純粋関数にできる部分は純粋関数にしているか

### 🟢 理想 (v2.0〜)
- [ ] 副作用のある処理を分離しているか
- [ ] テストしやすい構造になっているか

---

## 7. コンポーネント・クラス

### 🔴 必須 (v0.1〜)
- [ ] コンポーネントの責務が明確か
- [ ] propsの型定義があるか
- [ ] 1ファイルが大きすぎないか（目安: 300行以内）

### 🟡 推奨 (v1.0〜)
- [ ] 再利用可能な部分を共通コンポーネントに切り出しているか
- [ ] ビジネスロジックとUI表示が分離されているか

### 🟢 理想 (v2.0〜)
- [ ] クリーンアーキテクチャの層分けを守っているか
  - domain/: モデル定義
  - application/: ユースケース（ビジネスロジック）
  - infrastructure/: 外部サービス連携（Firebase等）
  - presentation/: UI

---

## 8. 条件分岐・処理の流れ

### 🔴 必須 (v0.1〜)
- [ ] 早期リターンを活用しているか
- [ ] ネストは浅いか（目安: 2階層以内）
- [ ] 条件式がシンプルで読みやすいか

### 🟡 推奨 (v1.0〜)
- [ ] 複雑な条件式は説明変数で分割しているか
- [ ] 否定形の条件（!isXxx）を避けているか

---

## 9. コメント

### 🔴 必須 (v0.1〜)
- [ ] コードを見てもわからない「なぜ」をコメントしているか
- [ ] 古いコメントが残っていないか
- [ ] TODO/FIXMEには担当者や期限を書いているか

### 🟡 推奨 (v1.0〜)
- [ ] 関数の目的を簡潔にコメントしているか
- [ ] 複雑な処理の全体像をコメントしているか

---

## 10. Firestore

### 🔴 必須 (v0.1〜)
- [ ] セキュリティルールで適切なアクセス制御をしているか
- [ ] householdIdによる絞り込みができているか（他家族のデータにアクセスできない）
- [ ] 必要なインデックスを作成しているか

### 🟡 推奨 (v1.0〜)
- [ ] クエリのパフォーマンスを考慮しているか
- [ ] リアルタイムリスナーの解除を忘れていないか（useEffectのcleanup）
- [ ] バッチ書き込みを活用しているか

### 🟢 理想 (v2.0〜)
- [ ] 読み取り/書き込み回数を最小化しているか
- [ ] オフライン対応を考慮しているか

---

## 11. Firebase Functions

### 🔴 必須 (v0.1〜)
- [ ] エラーハンドリングができているか
- [ ] ログ出力をしているか（logger.info/error）
- [ ] タイムアウト設定は適切か

### 🟡 推奨 (v1.0〜)
- [ ] 冪等性を考慮しているか（同じリクエストを複数回実行しても結果が同じ）
- [ ] 重複実行の防止ができているか

---

## 12. 状態管理（Zustand）

### 🔴 必須 (v0.1〜)
- [ ] グローバル状態は必要最小限か
- [ ] コンポーネントローカルで十分な状態をグローバルにしていないか

### 🟡 推奨 (v1.0〜)
- [ ] 状態の更新ロジックが適切な場所にあるか
- [ ] 不要な再レンダリングを避けているか

---

## 13. エラーハンドリング

### 🔴 必須 (v0.1〜)
- [ ] ユーザーにわかりやすいエラーメッセージを表示しているか
- [ ] ネットワークエラーを考慮しているか
- [ ] エラー時にアプリがクラッシュしないか

### 🟡 推奨 (v1.0〜)
- [ ] エラーの種類に応じた適切な対応をしているか
- [ ] リトライ機能が必要な箇所で実装されているか

### 🟢 理想 (v2.0〜)
- [ ] エラー監視サービス（Sentry等）への連携
- [ ] エラー発生時の自動復旧

---

## 14. UI/UX

### 🔴 必須 (v0.1〜)
- [ ] ローディング状態を表示しているか
- [ ] タップ領域は十分な大きさか（44pt以上推奨）
- [ ] 長いテキストの省略/折り返しを考慮しているか

### 🟡 推奨 (v1.0〜)
- [ ] キーボード表示時のレイアウト崩れがないか
- [ ] 空状態（データがない時）の表示があるか
- [ ] アクセシビリティを考慮しているか

### 🟢 理想 (v2.0〜)
- [ ] アニメーションが適切か
- [ ] ダークモード対応

---

## 15. セキュリティ

### 🔴 必須 (v0.1〜)
- [ ] 機密情報（APIキー等）をコードにハードコードしていないか
- [ ] .envファイルがgitignoreに含まれているか
- [ ] Firestoreルールでデータアクセスを制限しているか

### 🟡 推奨 (v1.0〜)
- [ ] ユーザー入力値のバリデーションをしているか
- [ ] 認証状態のチェックが適切か

---

## 16. テスト

### 🟡 推奨 (v1.0〜)
- [ ] 主要なユースケースの手動テスト手順を文書化しているか
- [ ] バグ修正時に再現手順を記録しているか

### 🟢 理想 (v2.0〜)
- [ ] ユニットテストを書いているか
- [ ] 境界値テストをしているか
- [ ] E2Eテストを導入しているか

---

## 17. リリース

### 🔴 必須 (v0.1〜)
- [ ] 後方互換性を考慮しているか
- [ ] app.jsonのバージョンを更新したか
- [ ] 動作確認チェックリストを実行したか

### 🟡 推奨 (v1.0〜)
- [ ] リリースノートを作成しているか
- [ ] ロールバック手順を確認しているか

### 🟢 理想 (v2.0〜)
- [ ] 段階的ロールアウトを検討しているか
- [ ] Feature Flagで機能を制御しているか

---

## クイックチェック（PR前の最終確認）

毎回のPR前にこれだけは確認:

- [ ] `npx expo start` でエラーなく起動するか
- [ ] 実機で主要機能が動作するか
- [ ] console.log/デバッグコードを削除したか
- [ ] 未使用のimport/変数がないか
- [ ] セルフレビューで差分を確認したか
